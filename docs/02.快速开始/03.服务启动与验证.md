# 服务启动与验证

<div class="doc-lead">按照依赖关系组织启动，并验证真正的业务闭环。</div>

## 建议启动层次

<Flow :steps='["数据库与基础设施","配置与服务发现","账户及业务 Provider","交易与行情服务","HTTP 接入与前端"]' />

这是依赖层次示意。实际启动顺序取决于注册发现、初始化缓存和调用方的启动检查配置。

## 启动后验证

| 验证层次 | 通过标准 |
| --- | --- |
| 进程 | 应用完成初始化，无依赖连接错误 |
| 服务发现 | 调用方可以发现并调用目标服务 |
| 数据 | 币种、交易对、商户与测试账户准备完整 |
| 交易 | 可提交订单、查看状态并完成撤单或成交 |
| 账务 | 余额和流水能解释每一次变动 |
| 行情 | 深度、成交与推送能随业务变化更新 |

## 系统访问

客户端与管理端需要分别检查路由、接口代理和商户上下文。页面可以打开只说明静态资源可用，不代表交易服务已就绪。
