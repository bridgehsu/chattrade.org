# 工程结构

<div class="doc-lead">认识独立服务与业务域聚合工程的组织方式。</div>

## 服务不是一个单体应用

Coinex 工作区由多个独立 Maven 服务或业务域聚合工程组成。根目录中的业务名称方便定位职责，但不意味着存在一个统一启动入口。

| 常见子模块 | 职责 |
| --- | --- |
| api | 跨服务接口、业务对象与枚举 |
| provider | 服务实现、数据访问与任务 |
| core | 核心计算与领域逻辑 |
| es | 搜索索引、查询或同步 |
| admin / web | 管理或用户 HTTP 接入 |

## 找到一条业务链

以现货为例，先找到委托服务，再辨认撮合、账户和行情依赖。合约与期权拥有自己的核心计算，不能把现货撮合链直接套用到所有交易产品。
