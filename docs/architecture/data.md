# 数据存储与缓存

<div class="doc-lead">区分业务事实、运行态数据和查询视图。</div>

## 数据分工

业务数据库记录账户、委托、成交、配置等持久化信息。缓存与撮合内存承担快速访问和运行状态维护。搜索索引、报表与推送属于面向查询的派生视图。

## 数据关系

| 对象 | 必须回答的问题 |
| --- | --- |
| 订单 | 谁在什么规则下提交了多少数量？ |
| 成交 | 哪些订单以什么价格完成了多少交易？ |
| 流水 | 哪个业务事实导致哪类资产发生变化？ |
| 缓存 | 数据从哪里加载，何时更新，失效后如何恢复？ |

## 恢复设计

在已检查的现货撮合实现中，可见未完成委托查询、初始化撮合事件以及本地存储相关逻辑。恢复时不仅要重建盘口，还要确认恢复边界，防止历史成交或资金事件被重复应用。

缓存与持久化之间的具体权威关系必须逐服务确认，不能一概把缓存称为可随时丢弃的数据。
