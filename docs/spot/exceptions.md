# 异常处理与一致性保障

<div class="doc-lead">用订单、成交和账务事实共同判断结果。</div>

| 场景 | 设计上应如何处理 |
| --- | --- |
| 提交后超时 | 使用原业务标识查询，先确认是否受理 |
| 余额不足 | 拒绝占用，避免订单进入可成交状态 |
| 撤单时继续成交 | 按权威处理顺序确认剩余量，再解冻 |
| 成交消息重复 | 按成交唯一标识识别已处理结果 |
| 结算只完成部分动作 | 保留处理中状态与恢复任务，核对每条账务事实 |
| 撮合重启 | 恢复未完成委托及处理边界，避免重放已结算资金 |

## 检查方法

沿业务编号核对委托、成交、占用、扣款与入账。只看页面余额或最后一条报错无法判断完整结果。异常修复应留下原因、审核和处理记录。

这些是应满足的设计目标。工程中可见撮合恢复、事件处理和资金相关实现，但是否覆盖所有异常需要运行测试与部署核查。
