# 整体架构

<div class="doc-lead">用户请求、资金事实、成交事实与行情展示组成四条相互协作的主线。</div>

<Flow :steps='["客户端 / 管理端","HTTP 业务接入","用户 · 账户 · 交易服务","撮合 / 结算","账务记录与行情分发"]' />

## 四类职责

| 职责 | 关注点 |
| --- | --- |
| 业务接入 | 身份、权限、参数、商户上下文 |
| 交易处理 | 委托、订单顺序、撮合或产品结果计算 |
| 资金处理 | 可用、冻结、扣款、入账与流水 |
| 查询分发 | 订单展示、报表、行情及实时通知 |

## 架构原则

订单状态、资金记录和行情展示不应互相替代。成交是否发生应由成交事实证明，资金是否入账应由账务事实证明，客户端推送只是帮助用户感知变化。

## 工程映射

现货链可见委托与撮合模块；合约有独立委托和撮合模块；期权有周期与结算实现；钱包连接链上资产与内部账务。它们共享用户、商户和公共能力，但拥有不同的业务状态机。
