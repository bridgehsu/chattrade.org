# 消息、上传与国际化

<div class="doc-lead">公共服务失败时，业务结果和用户通知应分别判断。</div>

## 消息、短信与邮件 {#messages}

业务成功和通知成功是两个结果。订单已完成但短信发送失败，不应回滚交易。通知重试需要防重复、限频与敏感信息处理。

## 文件上传 {#upload}

区分公开内容与身份认证、申诉等私密材料。上传应验证文件类型、大小、归属与访问权限，不能因为拿到链接就获得永久访问权。

## 国际化 {#i18n}

业务错误应有稳定含义，再映射为不同语言文案。翻译变化不应改变错误的处理方式；金额、时间和产品名称需要统一展示约定。

## 定时任务 {#tasks}

任务应记录执行范围、游标、结果和重试依据。多实例部署时需要考虑重复触发，尤其是周期结算、奖励发放与资金归集。
