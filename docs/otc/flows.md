# 核心交易流程

<div class="doc-lead">从发布广告到放币，并覆盖取消与申诉分支。</div>

## 广告发布 {#advert}

商家设置币种、价格、数量、限额和支付方式，平台验证资格与资金条件后开放展示。修改广告不应悄然改变已有订单约定。

## 下单与付款确认 {#payment}

<Flow :steps='["用户选择广告","校验并创建订单","占用数字资产","买方线下支付","买方标记已付款","卖方核实收款"]' />

## 放币与成交 {#release}

收款确认后，按订单处理数字资产转移、费用和状态。放币动作应具有权限检查与重复保护，订单完成需能关联资金记录。

## 取消与超时 {#cancel}

未付款取消、超时关闭和付款后争议需要区分。超时释放资产前应检查最新状态，不能忽略已付款或申诉动作。

## 申诉处理 {#appeal}

<Flow :steps='["发起申诉","保留订单与资金状态","收集双方凭证","审核判定","执行放币或退回","记录处理依据"]' />

申诉结果影响资产归属，必须记录操作者、原因、证据与资金动作。本文描述业务目标，不保证所有部署已启用同样审核环节。
