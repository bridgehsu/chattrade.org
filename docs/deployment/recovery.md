# 监控、备份与恢复

<div class="doc-lead">同时观察服务健康、业务积压和资金差异。</div>

## 日志、监控与告警 {#monitor}

监控应覆盖请求错误率、远程调用延迟、消息积压、撮合处理延迟、行情新鲜度、待结算订单、提现积压和对账差异。单个 CPU 指标无法证明业务健康。

## 备份与恢复 {#backup}

明确备份对象、恢复点与演练方法。恢复数据库之后，还需检查撮合运行态、消息进度、链扫描高度及已执行的外部付款，避免历史任务再次付款或入账。

## 恢复验证

先以只读方式核查订单、成交和账务事实，再逐步恢复写入。恢复成功的标准应包括资产核对、订单一致、行情同步和异常任务可追踪。
